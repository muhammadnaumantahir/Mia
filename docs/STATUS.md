Office DOCX/XLSX/PPTX ingestion now preflights ZIP entry count, expanded size, member size, encryption and compression ratio before invoking parsers; adversarial archive tests were added. Owner-triggered retention purge (`POST /api/memory/purge`, dry-run by default, audited) is implemented; the assistant sidebar has a preview-then-confirm cleanup panel (page script syntax-checked only, not browser-tested); no automatic expiry. Parser integration and broader hostile-document testing remain |
| 6. Autonomous agent | Manual execution + opt-in background read-only dispatch | Task Desk proposes/reviews tasks and supports approve/reject/cancel. The API can manually execute registered read-only tools; when MIA_AUTONOMY_ENABLED=true, the background worker filters for already-approved system resource/process/allowlisted-app inventory tools only. It checks CPU/RAM, exposes pause/resume, persists the owner pause across restarts, and records minimal Observatory events. Other tools remain queued for manual flows; interrupted tasks are now recovered to failed with an audit event and require owner re-approval before retry. Bounded 2-5 step read-only sequences check the live task state and autonomy pause between steps, so owner cancellation/pause prevents the next step from starting; an in-flight OS call is not forcibly terminated. Task claims now carry a durable lease (owner + expiry, renewed each step) so startup recovery and a per-cycle expired-lease check do not fail work held by another live process; leases are verified only with local unit tests. Automatic continuation across restart and target-device checks remain open |
| 7. Self-programming | AI draft + Capability Lab + Docker validation | Mia can draft a pure-Python run(input_data) module and pytest file using free-only model routing; drafts are reviewed in-browser and must be explicitly saved. The Lab stores immutable source/test versions, runs Docker validation and registers only passing versions. Registered permission-free candidates can also run once in a fresh isolated Docker container with JSON input/output limits; no runtime hot-loading is enabled. An owner-approved promotion and rollback record exists behind `MIA_CAPABILITY_ACTIVATION_ENABLED` (off by default): permission-free registered versions only, one active version per capability, rollback restores the previous one; it records the approved version and does not load or run code in the Mia process, and is verified only by local unit tests. Windows verification and the permission broker remain, and promotion has no UI |
| 8. 30-day experiment | Day 0, explicit start, host verification and optional daily scheduler implemented | Baseline is captured on the Mia host with Ruff, the separately versioned fixed benchmark suite and the full evolving regression suite; all must pass and the manifest is frozen by hash. Daily snapshots are server-generated, resource-aware and can be manually triggered or automatically scheduled after explicit experiment start. Missed days are recorded unavailable; a run that misses its final capture window becomes terminally incomplete, never completed. The report API/viewer verifies stored Day 0 and daily evidence hashes and distinguishes completed from incomplete runs. No real Windows-host baseline, 30-day run or evidence-backed final results exist yet |

## Not complete

Mia is not yet a finished personal assistant. General multi-step autonomous execution, verified OS-level sandbox, a permission broker for activation of permissioned capabilities on the target PC, always-on wake word, real desktop interaction and the actual 30-day experiment remain incomplete.

No Day 0 or daily growth data may be fabricated. Daily snapshots require local host verification and are not auto-filled when Mia is offline.

## Phase completion rule

A phase is complete only after roadmap exit criteria, relevant Windows/Linux tests, target-device checks, security/license review, and evidence tied to the exact commit and successful workflow run.
